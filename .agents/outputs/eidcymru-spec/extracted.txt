Introduction 
 
 
This document describes and specifies a Web Service interface to EIDCymru Web 
Service (EWS).  The interface is for Animal movement and associated data, 
submission and recovery. This document is intended for application suppliers to 
enable movement registrations to be made from external (to EIDCymru) systems and 
allows the client, the movement data supplier’s, system invoking this service – to do 
the following: 
• 
Submit movement into the EIDCymru Upload process. 
• 
Request data of previously submitted movement using EIDCymru reference 
(Mid).  
• 
Request data of previously submitted movement using Clients own reference 
(ExternalReference) 
• 
Accept receipt of Animals following movement from third parties. 
• 
Request listing of historic animal movement. 
• 
Get Current Registered Holdings  
 
 
1.1 
Assumed Knowledge 
 
 
This document assumes the reader is familiar with the concepts, acronyms and syntax 
of XML, XML Namespaces, Web Services and SOAP messaging.  They should also 
have a general appreciation of WS-Security standards 
(http://schemas.xmlsoap.org/specs/ws-security/ws-security.htm). 
 
1.2 
EIDCymru Registration Details: 
 
 
*To register, please contact the EIDCymru Service: 
e-mail: contact@eidcymru.org 
Telephone: 01970 636959 
 
 
1.3 
Application Name 
 
 
Each software provider requires an Application Name that must be specified when 
sending requests to EWS. The Application Name can be obtained from the EIDCymru 
Service.

Purpose 
 
 
The overall purpose of the document is to specify the interface to the service and its 
expected behaviour.  This behaviour includes response on successful completion of 
the service, or all possible error or warning conditions that may occur. 
The document is a user guide to the service.  It does not cover details on 
implementing a client application that calls this service, but intends to provide enough 
information for the reader to implement such a client.

4.1 
Introduction 
 
 
This section is intended for an audience external to EIDCymru that is intending to 
implement a client of the service described herein.   
 
4.2 
Web Services Security 
 
 
All client systems invoking EIDCymru services, will be supplied credentials to access 
the application from the EIDCymru Service. 
When calling this service, security information must be provided in the SOAP Body of 
the request, as follows: 
 
 
<soapenv:Envelope 
xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/" 
xmlns:ews="https://ews.eidcymru.org/ews/"> 
   <soapenv:Header/> 
   <soapenv:Body> 
      <ews:CreateMovementRequest> 
         <UserName>?</UserName> 
         <Password>?</Password> 
         <ApplicationName>?</ApplicationName> 
         <ApplicationVersion>?</ApplicationVersion> 
         <!--Optional:--> 
         <ApplicationKey>?</ApplicationKey> 
         <SchemaVersion>?</SchemaVersion> 
         <Timestamp>?</Timestamp> 
         <Movement></Movement> 
      </ews:CreateMovementRequest> 
   </soapenv:Body> 
</soapenv:Envelope> 
 
 
 
The provided credentials are used within the Security element of the SOAP message. 
Note: Client systems will be provided with security credentials upon request. 
The secure HTTPS transport protocol is used to invoke the Web Service.  No element 
of the SOAP message is otherwise encrypted.

4.3 
Warning Responses and SOAP Fault Errors 
 
 
4.3.1 
Introduction 
 
 
This section describes a common element of the Response from the service. 
If a service request message cannot be processed (e.g. invalid message format, 
internal system error), then a technical fault will be returned within a SOAP fault 
response.   
If however, a service call has been successfully received and processed, but the 
content of the message has violated some validation routine or failed some application 
logic a successful SOAP response will be returned, with the Business Warning (i.e. 
application error or warning) contained within a bespoke structure.  
 
 
4.3.2 Errors resulting in a SOAP Fault Response 
 
 
When processing fails and the Response message cannot be populated, a SOAP 
Fault message is returned.  The use of this SOAP Fault facility avoids having to have 
every field in the Response as optional.  Please refer to section 7.2, for the full list of 
scenarios that can cause a SOAP Fault (severe Error) and for the Error Codes and 
Messages returned in those scenarios. 
 
 
<SOAP-ENV:Envelope xmlns:SOAP-
ENV="http://schemas.xmlsoap.org/soap/envelope/" 
xmlns:ns1="https://ews.eidcymru.org/ews/"> 
   <SOAP-ENV:Body> 
      <ews:UpdateMovementResponse> 
         <SubmissionId>1662</SubmissionId> 
         <Failures> 
            <Failure> 
               <Code>S0011D</Code> 
               <Description>No Record Found</Description> 
               <Element>mid</Element> 
            </Failure> 
         </Failures> 
      </ews:UpdateMovementResponse> 
   </SOAP-ENV:Body> 
</SOAP-ENV:Envelope> 
 
 
4.4 
Service and Interface Namespaces 
 
 
For consistency and maintainability reasons the XML data types making up the 
Request and Response messages for a service are defined across a number of 
namespace layers.  The dependencies between these layers are strictly controlled to 
ensure reusability and to minimise the impact of any changes. 
The split across layers is such that the Request and Response messages for a service 
are defined at one namespace layer, and the component elements that make up those 
Requests and Responses are defined at a lower level.  The latter does not ever refer 
to the former.

5.1 Accept Movement Operation:  (AcceptMovementRequest) 
 
 
This operation is invoked to acknowledge and accept movements arriving at the 
client’s location. 
The operation accepts the request message, performs schema validation and then 
process the Animal movement within the EIDCymru system.  The response message 
returned indicates whether the message was successfully processed, or whether the 
movement acceptance was rejected by the EIDCymru system. 
 
 
5.1.1 
Pre-Conditions 
• 
The client system must be a registered* client of the EIDCymru 
system.Mid (Movement ID)- required 
• 
ArrivalDate–optional 
• 
MovementDoa - optional 
 
 
5.1.2 
Post Conditions 
 
 
5.1.2.1 Success Conditions 
The movement registration record will be stored within the EIDCymru system 
and a unique reference number returned for each record stored. 
 
 
5.1.2.2 Failure Conditions 
If the message fails schema validation or fails authentication, a SOAP Fault 
is returned as the response.   
Failure scenarios are described in full in section - 7

9 
End-User Setup - Advisery Notice 
 
 
This section provides advisery details which can be relayed to end users who wish to 
setup a software link to their EIDCymru online account. 
 
9.1.1 
Pre-Requisite 
Each individual keeper needs to have registered via the website 
www.eidcymru.org for a standard EIDCymru account. 
 
They should ensure details have been fully entered to their online account. 
 
Specifically: 
• 
Name and address details 
• 
The primary farm CPH and any other CPH numbers that form part of 
the holding/farm. 
 
 
9.1.2 
Enable Interface Credentials 
To enable their farm software link, the user is required to contact the 
EIDCymru Bureau directly via email or phone. 
They will need to provide: 
 
• 
EIDCymru Username  
• 
Primary farm CPH number 
• 
Name of their farm software package. 
 
The bureau service will activate the user’s web account to work with the 
specified farm software package. 
 
The credentials used for interfacing via farm software will remain the same 
as the keeper’s web site credentials. 
 
 
9.1.3 
Contact Details for User Support 
To register or ask for assistance, please contact the EIDCymru Service: 
 
e-mail: contact@eidcymru.org / cysylltu@eidcymru.org
